# MindLumi 티스토리 발행 절차서 - ⛔ 2026-11-16 중단

운영자 결정: 실익이 없고 제약만 많다(로그인 만료·일일 한도·수동 편집기). 예약 작업을 껐다. 이 문서는 기록으로만 남긴다.
이미 올린 글(mindlumi.tistory.com/1)은 그대로 둔다. 다시 시작하라는 말이 있기 전에는 아무것도 올리지 않는다.

예약 작업 「MindLumi 티스토리 주간 일괄 발행」(일요일 10:10)이 이 문서를 읽고 그대로 수행한다.
그 주 화·목·토에 네이버로 나간 글 3편을 구글용으로 다시 써서 일요일에 한 번에 올린다 (운영자 지정 2026-11-16).
왜 한 번에: 티스토리(카카오) 로그인이 며칠 못 가 풀린다. 주 3회로 나누면 그때마다 멈춘다. 주 1회면 로그인 확인도 주 1회다.

★완전 자동이다. 운영자가 모든 단계를 사전 승인했다. 질문하지 않고 검수를 기다리지 않는다.
  대신 발행 전 자가검증([4])과 발행 후 확인([6])은 어떤 경우에도 건너뛰지 않는다.
★이 절차에서 새로 알게 된 것은 묻지 않고 이 문서에 바로 반영하고, 보고에 무엇을 바꿨는지 1줄 남긴다.

역할 분담: 재작성·최종 판단은 직접 한다. 기계 점검 같은 반복 작업은 Agent 도구로 model "sonnet" 하위 작업자에게 맡겨도 된다.

## [0] 준비

- TZ=Asia/Seoul date 로 오늘 확인.
- Projects 도구로 JAMI 프로젝트 문서 `claude/tistory-ops.md`(발행 절차·가독성 스타일·일일 한도)와 `claude/content-ops.md` §3-1(금지선)을 읽는다.
- 저장소에서 읽는다: `mindlumi/index.json`(글 목록), `mindlumi/playbook.md`(지금 쓰는 공식), `mindlumi/tistory/`(기존 원고 - 형식 참고).
- uplika 커넥터가 안 보이면 RefreshMcpTools.

## [1] 올릴 글 고르기 (한 회차 최대 3편)

```
0순위  index.json 에 tistoryPending: true 인 글이 있으면 그것부터 처리한다
       수정 화면(tistoryEditUrl)을 열어 완료 → 공개 → 공개 발행만 한다. ⛔ 본문을 덮어쓰지 않는다
       이미 공개돼 있으면 주소만 기록한다. 이 경우에도 아래 1순위 글을 이어서 올린다
1순위  최근 10일 안에 네이버에 실제로 발행됐고 index.json 에 tistoryUrl 이 없는 글 전부, 오래된 것부터 최대 3편
       한 편씩 [2]~[7]을 끝내고 다음 편으로 간다. 한 편이 막혀도 나머지는 계속한다
       uplika list_channel_posts (accountId "conn_1454e4b39c72db9a", workspaceId "ws_f7979700dc84fc70") 로
       실제 발행 여부를 확인한다. 예약 상태로 아직 안 나간 글은 건너뛴다
⛔     excludeReason 이 있는 글(정치인 등)은 고르지 않는다
없으면  「이번 회차 - 올릴 글 없음」 한 줄 보고하고 끝낸다
```

원문은 uplika open_post 또는 get_post 로 읽는다. ⛔ 네이버를 브라우저로 열지 않는다(차단돼 있다).
한 회차에 새로 쓰는 글은 3편까지다. 글 사이에 2~3분 간격을 둔다.

## [3] 금지선

- 실명 인물 글은 보도된 사실만. 「명반에서는 이렇게 읽힌다」로 쓰고 단정하지 않는다. 제3자(배우자·상대방·가족) 실명 금지. 정치인 금지.
- 상장사 인물 글에 주가 전망으로 읽힐 표현 금지.
- 자녀 관련 금지어(요절·단명·질병·장애·불효·공부 못함·자녀 수 단정) 금지. 「깎인다」 계열 금지. 흉격 이름 본문 노출 금지.
- 실고객의 이름·이메일·생년월일시를 글·로그·보고에 쓰지 않는다.

## [4] ★발행 전 자가검증 - 통과 못 하면 발행하지 않고 고친다

```
① 스크립트로 세어서 수치를 남긴다
   본문 3,000자 이상 / h2 6개 이상 / table 1개 이상 / 이미지 3장 이상 / 인물 글이면 명반 캡처 2장
   mindlumi.ai 링크 1개 이상이고 ref=tistory / blog.naver.com 링크 0
   em·en 대시 0 / 「컴퓨트」 0 / ** 0 / 네이버 원문과 같은 문장이 30% 미만
② 모든 이미지 URL 이 실제로 열리는지 확인한다 (curl -sI 로 200)
③ 명반 서술과 뉴스 사실이 네이버 원문과 어긋나지 않는지, [3] 금지선 위반이 없는지 읽어서 확인한다
④ 이전 티스토리 원고 1편과 나란히 놓고 더 읽기 어렵지 않은지 본다
세 번 고쳐도 통과 못 하면 발행하지 않고 보고한다
```

## [5] 발행 - `claude/tistory-ops.md` §4 절차 그대로

- ★Claude in Chrome 으로 한다. 티스토리 로그인은 Chrome 에만 있다. ⛔ 내장 브라우저는 로그인 세션이 없어 쓸 수 없다.
- ⛔ 운영자가 보고 있는 기존 탭을 쓰지 않는다. tabs_create_mcp 로 새 탭을 만들고 끝나면 닫는다.
- 로그인 화면이 뜨면 발행만 건너뛴다. 원고는 [2]까지 써서 저장소에 커밋해 두고 index.json 에 tistoryDraft 경로를 적는다.
  점검 작업이 로그인이 돌아온 것을 보면 그 원고로 바로 올린다. 비밀번호는 다루지 않는다.
- https://mindlumi.tistory.com/manage/newpost/ → 제목(#post-title-inp 네이티브 세터 + input 이벤트)
  → 본문은 페이지에서 저장소 raw URL 을 fetch 해 tinymce.get('editor-tistory').setContent(html) 후 save()
  → 가독성 인라인 스타일 일괄 주입(table·th·td·h2·p·img) 후 다시 setContent + save(), textarea 에 input 이벤트
  → 카테고리 선택(명반 해석 / 자미두수 기본 / 자미두수 전서 / MindLumi 서비스 중 네이버 글과 같은 것)
  → 완료 → 공개 → 공개 발행
- ⚠️ 클릭 직전마다 스크린샷을 새로 찍어 버튼 위치를 확인한다. 창 크기에 따라 좌표가 달라진다.
- ⛔ 감리 블로그(sureview26, sureview.tistory.com)는 손대지 않는다. 기존 글을 지우거나 덮어쓰지 않는다.

## [6] ★발행 후 확인 - 건너뛰지 않는다

- https://mindlumi.tistory.com/ 을 열어 글이 실제로 공개돼 있는지 본다.
  일일 한도(계정당 15건, 감리 블로그와 공유)를 넘기면 에러 없이 비공개로 되돌아간다.
- 글을 열어 이미지가 전부 뜨는지, 표 테두리와 문단 간격이 정상인지, 카테고리가 맞는지 확인한다. 어긋나면 수정 화면에서 고친다.
- 비공개로 되돌아갔으면 그대로 두고 재시도하지 않는다. index.json 에 tistoryPending: true 와 tistoryEditUrl 을 적어 둔다. 다음 회차가 0순위로 처리한다.
