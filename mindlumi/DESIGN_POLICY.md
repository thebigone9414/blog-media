# MindLumi 디자인 정책

사이트(mindlumi.ai) · 숏츠 · 네이버 블로그 이미지에 같은 기준을 적용한다 (운영자 지정 2026-11-17).
주간 점검(일요일 사이트 점검, 월요일 주간 제작)은 이 문서를 읽고, 수치 결과와 함께 디자인 개선 추천을 낸다.
값은 2026-11-17 에 실제 코드에서 센 것이다. 코드가 바뀌면 이 문서도 같이 고친다.

## 1. 두 겹으로 나눈다

보는 곳마다 목적이 달라서 화면 전체 색은 다르게 두되, 이어 주는 요소는 고정한다.

```
눈길 겹   숏츠 · 릴스 · 틱톡 · 클립     1초 안에 멈추게 한다. 빨강 바탕 + 금색 강조
신뢰 겹   사이트 · 블로그 본문 이미지    읽고 결제를 믿게 한다. 흰 바탕 + 슬레이트 글자 + 파랑 버튼 + 앰버 강조
```

### 어디서나 같은 것 (이음 요소)
- 표어 「자미두수로 보는 내 사주」. 숏츠 머리줄, 유튜브 설명 첫 줄, 사이트 첫 화면에 같은 글자로 쓴다.
- 마크 「M MindLumi」.
- 강조색은 금·앰버 계열 하나. 숏츠 `#ffd84a`, 사이트 amber-700(`#b45309`) 글자 + amber-50(`#fffbeb`) 바탕.
- 별 캐릭터 얼굴(`_shorts/assets/mindlumi/face/<별>.png`). 숏츠에서 본 얼굴이 사이트·블로그에서도 같은 얼굴이어야 한다.
- 행동 문구 「내 원반과 제2명반 무료로 보기」. 버튼·배너·설명란에서 낱말을 바꾸지 않는다.
- 명반 그림은 실제 사이트 화면 그대로(`_tools/capture_chart.mjs`). 다시 그리지 않는다.

## 2. 신뢰 겹 - 사이트 · 블로그 이미지

```
글씨체   제목·명반  Gowun Batang → Noto Serif KR (tailwind font-serif)
         본문·버튼  Noto Sans KR (font-sans)
바탕     흰색 · slate-50
글자     제목 slate-800 · 본문 slate-600~700 · 보조 slate-400~500
선       slate-200 (연한 선 slate-100)
주 버튼  bg-blue-600, 누를 때 blue-700, 흰 글자. 한 화면에 채운 파랑 버튼은 하나만 둔다
강조     amber-700 글자 · amber-50 바탕 · amber-200 선 (무료·혜택·핵심 한 줄)
경고     red-50 바탕 + red-600~700 글자. 오류와 법정 고지에만 쓴다
모서리   카드 rounded-xl · 버튼과 입력 rounded-lg · 알약 rounded-full
블로그   소제목 #2563eb(=blue-600) 24px · 형광 밑줄 #fff593 · 구분선 line2
```

- 색을 새로 들이지 않는다. indigo · rose · emerald 는 지금 쓰는 자리(구분 표시) 밖으로 넓히지 않는다.
- 모바일 390px 에서 주 버튼은 엄지 닿는 아래쪽, 높이 48px 이상.
- 법정 고지(열람 시 환불 제한 등)는 크기·대비를 줄이지 않는다.

## 3. 눈길 겹 - 숏츠

```
바탕     빨강 방사형  #ff5a3c → #d1121f → #8a0b1c
강조     금색 #ffd84a (제목 강조 낱말 · 꼬리표 · 반짝이)
글자     흰색, 표 안은 #1c1020
글씨체   Noto Sans KR 굵게 (+ 이모지)
구성     머리줄(마크 | 표어 + 꼬리표) → 제목 2줄 이내 → 노란 알약 → 표 → 참여 버튼 → 주소 2줄
```

- 한 영상에 표 하나, 개념 하나. 표 값은 엔진 계산값만.
- 어두운 테마 · 밋밋한 단색 테마는 쓰지 않는다 (운영자 지적 2026-11-16).
- 세부는 `_shorts/mindlumi_rules.md` §1-1 · §1-2.

## 4. 결과를 디자인으로 읽는 법

주간 점검은 아래 표에서 「이번 주 결과」에 해당하는 줄을 찾아, 그 줄의 디자인 손잡이로 추천을 쓴다.
추천은 「결과가 이런데 → 디자인을 이렇게 바꾸면 → 어느 수치가 얼마나 움직여야 성공」 한 묶음으로 적는다.

### 사이트 (일요일)
| 결과 | 볼 디자인 | 바꿀 후보 |
|---|---|---|
| 방문 → 맛보기 생성이 낮다 | 첫 화면(스크롤 전) | 약속 한 줄 크기, 입력 칸과 주 버튼이 첫 화면 안에 있는지, 버튼 대비, 캐릭터 얼굴로 온기 |
| 맛보기 → CTA 클릭이 낮다 | 결과 화면 | CTA 위치(결과 바로 아래 · 모바일 하단 고정), 잠긴 영역의 미리보기 모양, 강조색 쓰임 |
| CTA → 주문·결제가 낮다 | 결제 칸 | 가격 위계, 포함 항목 목록, 신뢰 요소. ⛔ 결제 코드·가격·고지는 자동 수정 금지 - 시안과 제안만 |
| 맛보기 대기 중 이탈 | 로딩 화면 | 진행 표시, 기다리는 동안 보여 줄 것 |
| 숏츠·인스타·틱톡 유입만 전환이 낮다 | 도착 화면의 이어짐 | 숏츠에서 본 표어·얼굴·금색이 첫 화면에 있는지 (ref 별 이음 띠) |
| 블로그 유입만 CTA 클릭이 낮다 | 결과 화면 + 블로그 배너 | 글에서 약속한 것과 결과 화면 첫 줄이 맞는지 |

### 숏츠 (월요일)
| 결과 | 볼 디자인 | 바꿀 후보 |
|---|---|---|
| 조회수 자체가 낮다 | 첫 화면 1초 | 제목 크기·줄 수, 강조 낱말, 알약 문구, 첫 프레임 움직임 |
| 조회 대비 좋아요·댓글이 낮다 | 참여 버튼 | 버튼 위치·문구·맥동, 표에서 「내 줄」을 찾기 쉬운지 |
| 조회는 높은데 사이트 유입이 없다 | 아래 주소 2줄 | 앱 화면에 가려지는지, 위치를 올릴지, 표어와 주소의 대비 |
| 한 시리즈만 잘 된다 | 그 영상의 화면 | 잘 된 화면의 요소를 다른 시리즈에 옮긴다. 2주 연속 안 되는 시리즈는 내린다 |
| 채널별 차이가 크다 | 채널 규격 | 안전 영역, 자막 위치, 길이 |

⛔ 분모가 30 미만이면 그렇게 적고 단정하지 않는다. 한 회차에 바꾸는 것은 1~2건.

## 5. 적용 방식

```
정책에 맞추는 작은 수정   주 버튼이 둘이다, 강조색이 다르다, 모서리가 다르다, 표어 글자가 다르다 같은 것.
                          기존 자동 수정 범위 안이면 그대로 고치고 사후 보고한다
화면 인상이 바뀌는 수정   첫 화면 구성, 색 겹 변경, 새 띠·새 영역, 숏츠 새 화면.
                          Claude 디자인으로 시안 2~3개를 만들어 보고에 붙이고 운영자가 고른 뒤 반영한다
```

보고에는 「디자인」 줄을 넣는다: 결과 1줄 → 추천 1~3건(각각 바꿀 것 · 기대하는 수치 변화) → 시안 링크(있으면).
기록은 `site-log.md` · 주간 제작 기록에 「디자인」 줄로 남기고, 다음 회차에 그 수치가 움직였는지 먼저 본다.

## 6. 첫 추천 후보 (2026-11-15 기준선에서)

```
① direct 방문 138 중 맛보기 22 (16%). blog 는 62 중 44 (71%)
   → 첫 화면에서 무엇을 주는지와 주 버튼이 스크롤 전에 보이는지부터 본다. 가장 큰 누수
② blog 유입은 맛보기 뒤 CTA 클릭 36%, direct 는 64%
   → 결과 화면의 CTA 위치와 모양. 모바일 하단 고정 버튼 후보
③ 숏츠 유입은 30일 5건이라 판단 불가. 매일 숏츠가 나가기 시작했으므로 다음 회차부터 ref=shorts · insta · tiktok 을 따로 본다
   → 빨강·금색 영상에서 흰 화면으로 넘어오는 이음이 끊기는지 확인. 이음 띠 시안 후보
```
①~③은 가설이다. 일요일 점검에서 화면을 직접 보고 시안으로 확인한다.
