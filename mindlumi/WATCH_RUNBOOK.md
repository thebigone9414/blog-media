# MindLumi 자동화 점검 절차서

예약 작업 「MindLumi 자동화 점검」이 주중 06:15(하루 1회), 주말 08:25 · 10:25 · 15:25 · 22:25 에 이 문서를 읽고 수행한다.
다른 예약 작업이 돈 지 약 1시간 뒤에 결과를 보고, 안 나간 것은 이 작업이 직접 마저 한다.

★완전 자동. 질문하지 않는다. 승인 창이 뜨는 도구는 쓰지 않는다.
★예약 작업의 「성공」 표시를 믿지 않는다. 결과물(예약·발행된 글과 영상, 기록 파일)로 확인한다.
★발견한 문제는 「보고」가 아니라 「조치」가 먼저다. 다른 작업을 다시 돌리려 하지 말고(권한이 없다) 그 일을 직접 한다.
★조치할 게 없고 지난 점검과 달라진 것도 없으면 2분 안에 끝낸다. 매번 전부 다시 조사하지 않는다.

## 일정표 (KST) - 2026-11-18 변경: 주중은 제작·발행을 05~06시에 끝내고, 점검은 06:15 에 시작해 07:00 전에 끝낸다 (운영자 지정, 출근 전 완료)

주중에는 회차가 하루 한 번뿐이다. 그래서 아래의 「22:25 회차에 반드시」 하던 미디어 만료 대비를 주중에는 06:15 회차에 매번 한다.
주중에 05:40 발행분이 안 나갔으면(네이버 확장 offline · 로그인 풀림) 그 회차 보고 맨 위에 적는다. 운영자가 출근 전에 볼 수 있는 유일한 회차다.

## [2] 조치 - 직접 한다

```
이번 주 예약이 6건 미만 (월 06:15 회차)
    → mindlumi/WEEKLY_RUNBOOK.md 를 읽고 빠진 것만 직접 만든다. 인계 문서가 있으면 그 원고로 이미지부터 이어서 한다
      이미 예약된 건과 겹치지 않게 제목으로 대조한다
★미디어 만료 대비 (주중 06:15 회차마다 · 주말 22:25 회차에 반드시)
    uplika 에 올린 그림·영상은 올린 지 이틀 뒤 만료 시각이 찍힌다. 예약 글에 붙인 뒤에도 유지되는지는 문서로 확인되지 않았다
    → 앞으로 36시간 안에 나갈 예약 유튜브 글과 인스타그램·틱톡 글, 네이버 클립 글마다: 저장소 raw URL(mindlumi/shorts/<파일>.mp4, index.json·spec 이름으로 찾는다)에서
      media_from_url 을 다시 하고 update_post 로 mediaIds 만 갈아 끼운다 (mediaIds 만 보내면 제목·설명은 그대로다)
      ⚠️ 2026-11-18~ 네 채널(유튜브 · 인스타그램·틱톡 · 네이버 클립) 모두 움직임 판 `<파일>-m.mp4` (16초)를 쓴다 (운영자 지정). `-m.mp4` 가 저장소에 있으면 반드시 그것으로 갈아 끼운다. 11초 판으로 되돌리지 않는다
    → 앞으로 36시간 안에 나갈 예약 네이버 글마다: get_post 로 본문을 읽어 media:<id> 를 전부 뽑고, 같은 순서의 그림
      (index.json 의 images 경로 + CTA 그림)을 다시 media_from_url 해서 본문의 id 를 새 id 로 바꿔 update_post 한다
      ⚠️ options 를 같이 보낼 때는 title·categoryId·layout·openType·tags·seoKeywords 를 전부 다시 보낸다(빼면 지워진다). 본문만 바꿀 때는 options 를 보내지 않는다
    글 원고는 mindlumi/w<주차>/a1.md · a2.md · a3.md 에 있다({{IMG1}}~{{IMG4}} · {{CTA}} 자리 표시)
발행 실패(failed)
    → get_help 로 원인 확인 후 retry_post 1회. 또 실패하면 같은 내용을 새 publish 로 한 번. 그래도 안 되면 미해결로 적는다
네이버 글이 예약 시각을 1시간 넘겼는데 안 나감 (확장 offline)
    → 글은 확장이 돌아오면 나간다. 기다린다. 6시간 넘으면 미해결(운영자가 Chrome 을 봐야 함)
발행된 글·영상의 주소가 index.json 에 없음
    → url / youtubeUrl 을 채우고 status 를 published 로
사이트가 안 열리거나 Deploy failure
    → 최근 머지를 revert 커밋으로 되돌린다 (JAMI 문서 claude/site-improve.md [6]). 강제 푸시·reset --hard 금지
```

⛔ 하지 않는 것: 비밀번호·로그인, 결제·환불, 관리자 게이트, 프로덕션 DB, 예약 작업 삭제·재실행 시도.
⛔ 같은 조치를 하루 두 번 넘게 반복하지 않는다(watch-log 로 센다).

## [3] 기록과 보고

`mindlumi/watch-log.md` 맨 위에 추가하고 커밋·푸시.

```
## YYYY-MM-DD HH:MM
확인    지나간 칸 N개 - 나간 것 N / 안 나간 것 N
연결    네이버 확장 online|offline · 유튜브 ok
조치    직접 한 것 (없으면 「없음」)
미해결  운영자가 해야 하는 것 (없으면 「없음」)
```

보고는 문제가 있을 때만 길게 쓴다. 정상이면 한 줄: 「MM-DD HH:MM 점검 - N건 확인, 조치 없음」.
미해결이 생겼거나 풀렸을 때는 운영자가 해야 할 일을 맨 앞에 한 줄로 쓴다.
success/failure 로 쓴다. 이름·이메일·생년월일시 금지. 대시는 하이픈만.
